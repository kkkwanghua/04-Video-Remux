# 视频批量重封装工具 · 使用说明

一个**完全离线**的图形界面工具：批量扫描文件夹下的视频文件，**无损重封装**到指定容器格式（MOV / MP4 / MKV），可保留子目录层级。

**当前版本：v1.2.8**

---

## 一、快速开始

### 推荐：使用 .app 应用（无需任何依赖）
工作区根目录下有两个**完全自包含**的应用，内置 Python 运行时 + tkinter + ffmpeg，**目标电脑无需安装 Python、无需 ffmpeg、无需联网**。按芯片选择：

| 应用 | 适用机器 | 内置架构 |
|---|---|---|
| `视频重封装工具.app` | Intel Mac | x86_64 Python + ffmpeg |
| `视频重封装工具-arm64.app` | Apple Silicon（M 系列） | 原生 arm64 Python 3.13.18 + ffmpeg |

- **M 系列 Mac 直接用 `视频重封装工具-arm64.app`**（原生 arm64，无需 Rosetta 2，速度快）；Intel Mac 用 `视频重封装工具.app`。
- 双击打开即可；**可直接把文件夹拖入源/目标路径栏**（macOS 原生拖放，无需额外组件）；拖入文件时会自动取其所在目录。
- 版本号（v1.2.8）显示在窗口标题栏，应用菜单「关于」中也可查看。
- v1.2.0 修复了 MXF 等专业素材转 MOV/MP4 时因临时文件名导致的转换失败问题。
- **v1.2.1 修复了 NAS / Xsan 等网络存储环境下的问题**：① 扫描改为后台进行，不会因网络慢而"一直转圈"卡死；② 修复批量转换时窗口闪退（子线程误操作界面导致）；③ 单个文件出错不再中断整批；④ 增加崩溃日志（`/tmp/remux_crash.log`），若仍异常可据此排查。
- **v1.2.2 转换提速**：`moov 前置(faststart)` 改为默认关闭。该功能写好文件后会再把整个文件读写一遍，在 NAS/Xsan 上会让耗时近乎翻倍（如 24GB 从约 8 分钟变约 16 分钟）。
- **v1.2.3 彻底移除 moov 前置**：直接删掉该选项（不再有勾选框，命令中永不添加 `-movflags +faststart`）。本地、万兆内网 Xsan、NAS 全部走同一条最快路径——24GB 在万兆内网约 2 分钟完成，NAS 环境与 Xsan 速度一致。Mac 空格预览由独立的 hvc1 标签修正负责，不受影响。
- **v1.2.4 修复 NAS 批量转换 native 崩溃**：v1.2.1 只修了按钮状态的跨线程问题，遗漏了转换线程仍在读取 tkinter 变量（`fix_hev1_var.get()`）。Tcl/Tk 不是线程安全的，子线程访问会导致 `python3.13` 直接意外退出（系统崩溃对话框，Python 层日志抓不到）。现已把所有界面变量在主线程读成普通值后再传给后台线程，worker 内不再触碰任何 Tk 对象；同时启用 faulthandler，若仍发生 native 崩溃会把 Python 栈写入 `/tmp/remux_fault.log` 便于定位。
- **v1.2.5 修复拖放文件夹导致崩溃**：重写了原生拖放模块（`drop_target.py`）。旧版在 AppKit 回调栈内反复修改全局共享的 `objc_msgSend` 签名并重入，触发 native 崩溃；还缓存了会被回收的 autoreleased 字符串（野指针）。新版为每种消息签名创建**独立**函数指针互不干扰、用 alloc/init 持有字符串、`performDragOperation:` 返回类型修正为正确的 BOOL。拖放诊断日志写入 `<临时目录>/remux_drop.log`（终端执行 `open $(python3 -c 'import tempfile;print(tempfile.gettempdir())')` 可定位）。
- **v1.2.6 修复部分机器上拖放仍崩溃 + app 重签**：v1.2.5 只修了 objc_msgSend 签名，但拖放回调 `cb` 仍在 AppKit/ctypes 的**临时 Python 线程状态**里调用 `root.after()` 注册 Tk 命令；命令绑定到回调结束后即销毁的临时 tstate，Tcl 执行排队命令时 `PyEval_RestoreThread` 用悬空 tstate → 致命错误 → native SIGSEGV。是否触发取决于该机器 tstate 内存是否被复用（故"开发者机器正常、部分机器必崩"）。现改为：拖放/点击回调只把数据入队（`msg_queue`），路径栏更新与聚焦由主线程 `_poll_queue` 在正常 tstate 下完成，彻底消除跨线程/临时 tstate 的 Tk 访问。同时重新 ad-hoc 签名并清除隔离属性，修复"app 报损坏无法打开"。
- **v1.2.7 扫描后格式筛选**：扫描完成后，文件列表上方会按实际扫到的扩展名（如 MXF / MP4 / MKV）生成一组复选框，默认全选。取消勾选某个格式，该类文件即从待转换中排除；也可单击列表首列「选」（☑/☐）逐个文件勾选，或用「全选 / 全不选」批量操作。「开始转换」只处理勾选的文件，右侧显示「选中 N/总数」。格式筛选与逐行勾选是两道独立开关，互不覆盖，方便"扫出来一堆格式、只转 MXF 或 MXF+MKV"这类需求。
- **v1.2.8 多 mono 音轨兼容修复**：MOV / MP4 输出时显式把所有音轨标记为 default/enabled。ffmpeg 默认只把第一条音轨设为 default，Premiere 或播放器可能因此只显示/选中一条音轨；修复后 MXF 的多条 mono 音轨在 MOV 中保持全部可见。MKV 输出不改，避免播放器自动选轨异常。
- 若系统提示"无法打开，因为来自身份不明的开发者"：右键 → 打开；或终端执行 `xattr -dr com.apple.quarantine 路径/xxx.app`。
- 两个 `.app` 均可直接整包拷到对应架构的 Mac 使用。

### 备用：源码方式（需目标机自带 Python）
`RemuxTool/启动工具.command` 适用于已装 Python 3（带 tkinter）的电脑。

操作步骤：
1. **选择源文件夹**：要扫描视频的目录。
2. **选择目标文件夹**：输出目录（可与源目录不同）。
3. **选择目标格式**：MOV / MP4 / MKV（每次运行可选）。
4. 点击**扫描文件** → 确认列表 → 点击**开始转换**。

## 二、核心特性

- **无损重封装**：只拷贝视频/音频码流（`-c copy`），**不重新编码**，画质零损失，速度极快（通常远超实时）。
- **MXF → MOV 专项优化**：只提取主视频轨 + 全部音轨，自动跳过 MXF 的时间码/元数据等数据轨，避免 MOV 封装失败；MOV/MP4 输出会把全部 mono 音轨标记为默认/启用，避免只显示一条音轨。
- **HEVC 兼容性修复**：HEVC 视频自动打上 `hvc1` 标签，解决 macOS「空格快速查看」无法预览的问题（仅对 HEVC 生效，不会误伤 ProRes/DNxHD/H.264）。
- **安全机制**：先写临时文件并校验，通过后才原子替换；单个文件失败不影响其余文件；可跳过已存在文件。
- **保留子目录层级**：输出目录复刻源目录结构，避免同名文件互相覆盖。

### 典型用途
| 场景 | 目标格式 | 说明 |
|---|---|---|
| 大量 MXF 素材转 MOV | MOV | 剪辑素材归档，画质无损 |
| MKV / TS 转 MP4 | MP4 | 兼容性更好，手机/网页可播 |
| HEVC 文件空格预览失败 | MOV 或 MP4 | 自动修正 hvc1 标签 |

## 三、离线与依赖说明（重要）

本工具专为**无 ffmpeg、无网络**的环境设计，已做如下处理：

### 1. ffmpeg —— 已随工具打包 ✅
工具目录内的 `bin/ffmpeg` 是随附的可执行文件（77MB，静态编译，不依赖外部库）。
工具启动时**优先使用它**，因此目标电脑**无需安装 ffmpeg、无需联网**。

ffmpeg 探测顺序：
1. 工具自带 `bin/ffmpeg`（离线可用）
2. 系统 PATH 中的 ffmpeg
3. WorkBuddy 内置的 ffmpeg
4. 常见安装路径（Homebrew 等）

每个候选都会被**实际执行一次** `ffmpeg -version` 验证，跑不通的会自动跳过。

### 2. Python + tkinter —— 需要目标电脑具备 ⚠️
图形界面基于 Python 的 tkinter（标准库，无需联网安装第三方包）。

- 启动脚本会自动探测带 tkinter 的 Python。
- 如果目标电脑**完全没有 Python**，图形界面无法启动。解决办法二选一：
  - 在有网时安装 Python 3（python.org 的安装包默认含 tkinter）；
  - 或把本机带 tkinter 的 Python 环境一并拷贝到目标机器（见下方"整体拷贝"）。

### 3. 架构兼容性
源码方式随附的 `bin/ffmpeg` 是 **x86_64** 架构：
- 在 **Intel Mac** 上：直接可用。
- 在 **Apple Silicon（M 系列）Mac** 上：需要 Rosetta 2，或把 arm64 版 ffmpeg 替换 `bin/ffmpeg`。

> 💡 M 系列 Mac 推荐使用已打包好的 **`视频重封装工具-arm64.app`**（原生 arm64，无需 Rosetta、无需替换），不必用源码方式。

## 五、常见问题

**Q：双击 .command 提示"无法打开，因为来自身份不明的开发者"？**
A：右键点击 → 打开；或在"系统设置 → 隐私与安全性"里允许。

**Q：扫描不到文件？**
A：确认扩展名在支持列表内：mp4/mov/mxf/mkv/avi/ts/mts/m2ts/m4v/webm/flv/wmv/mpg/mpeg/vob 等。

**Q：某个文件转换失败？**
A：看日志里的 ffmpeg 报错。常见原因是源文件的编码组合无法直接拷贝进目标容器（极少数冷门编码），这种情况才需要重新编码（本工具不做重编码，以保证画质无损）。

**Q：应用意外退出（系统弹出"python3.13 意外退出"）？**
A：请查看两个诊断日志并反馈：`/tmp/remux_crash.log`（Python 异常）和 `/tmp/remux_fault.log`（native 崩溃时的 Python 调用栈）。v1.2.4 已修复转化线程的跨线程 Tk 访问崩溃，若仍复现，这两个日志能精确定位。

**Q：转换后体积几乎没变？**
A：正常。重封装只换"外壳"，码流原样保留，体积基本不变。
